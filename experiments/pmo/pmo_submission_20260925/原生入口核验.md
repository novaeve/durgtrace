# 原生架构接入核验

用户要求保留方法原有初始化、搜索和记忆；不存在的能力不由评测外层补齐。统一最多 1,000 次分子答案提交，重复/无效占次数，最终按首次生成序号去重并使用 MT-Mol AUC 公式。旧自定义搜索任务保持暂停。

## 已实现：DeepSeek 直接生成

此组是基础模型基线，不声称是一个有原生搜索架构的 agent。每个目标独立请求单个分子，最多 1,000 次；23 目标，单个重复实验。每次请求仅包含目标及单 SMILES 格式要求，无起始分子、候选库、历史、评分反馈或自动优化循环。temperature=0、thinking=false、deepseek-v4.1-flash 沿用已授权模型配置。相同答案继续占预算，不使用去重补抽。

每个请求的一个答案对应一次提交；空/无效为失败提交；格式仅移除完整 Markdown 代码围栏，不择优提取多个分子。因服务端上限截断的响应也计失败提交，部分长 SMILES 不进入 RDKit；累计 3 次按既有用户指令跳过当前目标。传输重试不计为答案；API 缓存重放不增加提交次数。

使用原评分环境及模型端点，不载入旧 adapters、Ledger、初始化或搜索循环。QED 前 3 次提交做同配置冒烟核验，随后复用原记录继续，避免重复调用；通过后 4 进程运行 23 个目标。

## 首次核验发现的入口限制

- ChatDrug：main_ChatDrug.py:109-111 通过 load_retrieval_DB 加载任务数据集的待编辑分子；随后遍历输入，构建带输入分子的 PDDS 提示，最多 C+1 次反馈。它读取的源 benchmark 输入数据不是 agent 自主生成初始候选的算法。当前没有给 PMO 擅自借用那 200 个输入，也没有补初始分子；尚无可确认的仅输入 PMO 目标的原生入口。状态 input_contract_mismatch，分数 null，非实测零分。
- AgentDrug：source/datasets/generation.py:9 读取任务 test.csv，__getitem__ 要求 SMILES/Text/modifiedSMILES；inference.py 对输入分子运行原生细化。未发现无起始分子的 PMO 入口，未用另一个任务的测试分子替代初始化。状态 input_contract_mismatch，分数 null。
- MolLingo：planner.py 从 agent 导入 LiteratureAgent、ChemistAgent；原 ZIP、本地 upstream、服务器 upstream 都缺少 agent.py。完整调用链未能装载，状态 missing_source，分数 null。已有 run_agent.py 还要求解析出 disease，main_task 限于 ADMET/DILI/hERG/AMES/Pgp/HIA/BBBP，不能把任意 PMO 目标擅自改成疾病或 ADMET。先前只调用的 optimize_mol_tomg 工具不替代完整 agent。

接口不适用、源码缺失与运行后分数低分别报告；不将未执行的 69 个方法×目标任务标作完成或计入均值。

需要完整 MolLingo 的 agent.py 及其依赖才能继续核验；不自行重写缺失 agent。对于只支持给定分子编辑的原程序，保持此输入边界，不增加公共初始化或搜索。

## 用户随后授权的模型起点接入

用户进一步明确让 ChatDrug、AgentDrug 由模型生成一个起始分子，并与 DeepSeek 对照组保持一致。已新增 run_editors.py 复用每个目标的首个对照组答案，再执行一次原生编辑流程。此为用户明确授权的初始化接口补充，不是新增跨轮搜索。具体预算、原始检索库、自然结束及 API 复用规则见模型起点编辑实验.md。此前 input_contract_mismatch 是授权这项补充之前的核验状态，不再作为这两组的最终阻塞结论。
