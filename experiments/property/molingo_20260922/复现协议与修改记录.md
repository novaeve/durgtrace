## 方法与数据

运行作者的 `toolset/optimize_mol.py::optimize_mol_tomg` 分子优化入口。它使用作者提供的 vocab20.json 拆分分子，将片段及化学名称写入提示词，调用模型提出 3 项片段替换，然后按原代码枚举片段组合并重组分子。本次不是疾病检索、ADMET 筛选、docking 的完整药物设计流程；压缩包也没有完整流程所需的 agent.py。

沿用既有 7,100 个实例及评价器：ChatDrug 200 个输入 × 28 个设置，共 5,600 条；S²-mini MolOpt 的 LogP、QED、MR 各 500 条，共 1,500 条。输入文件和评价器直接复用此前项目。原 benchmark 指令嵌入作者片段修改提示模板，不宣称最终完整提示词与其他方法逐字相同。

后端使用同一 DeepSeek 官方 deepseek-flash，temperature=0，thinking disabled，effort low，两线程并行。每个实例一次逻辑模型调用，网络失败沿用已有重试机制；未添加输出 token 上限，使用供应商默认值。原代码的 GPT Responses API / web_search 没有在 DeepSeek 端模拟，因此属于换后端复现，不是论文原模型成绩，也不宣称各方法调用数或 token 预算相同。

## 原代码的结构重组问题

对全部 1,695 个不同输入进行“不替换任何片段”的拆分重组检查：1,366 个完全一致，329 个发生改变，包括立体化学、连接方式或键型改变。详见 validation.json。该问题来自原 tokenizer / 重组逻辑。本次保留该实现，不悄悄改成新的化学算法，也不剔除这些输入。

每个实例额外记录无修改重组候选及其评价、roundtrip_changed 标志，分析时必须同时披露这部分结果。模型提出修改后的候选仍可能继承原重组问题，因此仅扣除无修改候选不能消除所有影响。

## 统计口径

作者入口返回候选列表，没有最终单分子选择器。3 项修改不等于最终只有 3 个候选，笛卡尔积会产生更多分子，而且包含无修改组合。

`result.json` 保留原组合池评价及全部候选，`summary.json` 是运行监控。正式分析使用 `audit.json`：

- `first_proposal_success`：按原枚举顺序取首个有效、且不同于输入和无修改重组输出的候选；无此候选计失败。不使用性质分数挑选。
- `proposal_pool_success`：上述模型修改候选中至少一个通过，属于候选池 oracle 指标，不能当作等预算单次输出成绩。
- `original_pool_success`：原程序整个组合池至少一个通过，包含无修改重组候选。
- `no_modification_success`：单独衡量不执行模型片段替换时重组产物的通过率。

报告应按 benchmark 分组，并分层检查 roundtrip_changed。不把当前监控中的 first_success 直接作为正式首个修改候选指标：它只排除了原输入，未排除发生变化的无修改重组产物。
