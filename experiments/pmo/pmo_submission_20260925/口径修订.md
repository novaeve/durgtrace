# PMO 提交预算修订（2026-09-25）

用户要求最多提交 1,000 次答案，重复去重但保留生成序号。旧 PMO 调度器及四个 worker 已 SIGSTOP 暂停，断点及结果未删除；服务器 paused_protocol_review.json 记录进程和时间。未自动重启新实验。

## 已明确的评价口径

- 预算为 1,000 次分子答案提交；重复答案和无效答案均占一次。不再补足 1,000 个不同有效分子。
- 多分子输出按提交顺序逐个计数，不能将整个列表当成一个分子答案。不得先免费评价整个列表再择优提交。
- 化学规范化后去重，保留首次提交位置。例如 A、A、无效、B 的位置为 A=1、B=4；不压缩为 1、2。
- AUC 使用 MT-Mol utils/auc.py 的 top_auc 公式，freq_log=1，横轴为首次提交序号，分母为 1,000。全无效时返回 0，避免原函数空数组异常。未结束运行不按完成状态补尾。
- API 请求、内部反馈读取、断点重放不等同于新增提交。稳定 event_id 防止断点恢复重复计数；新轮次再次交相同答案使用新 event_id，正常消耗预算。
- MT-Mol 原实现是一轮进入 Reviewer 记一条答案；多个内部 LLM 调用并不各自计作一次答案。适配不同 agent 时必须明确最终提交边界，以及内部 oracle 查询的独立账目，不能直接拿旧 episode 数量或旧 submissions.jsonl 当答案次数。

旧实现是分子编辑入口加自定义搜索外层：100 个 ZINC 初始化、当前前 100 名抽父分子、最近 20 个历史。不是 MT-Mol 的流程，也不能用来声称原 agent 自主搜索能力。

已核对 AgentDrug inference.py 及数据入口、MolLingo toolset/optimize_mol.py：此前使用的是给定分子的编辑路径。这并不证明完整 agent 没有其他初始化/生成入口；需要进一步核对完整调用链。

本目录 submission_budget.py 仅实现评价与提交记账，不加入初始化、选父分子、检索库或模型上下文策略。旧结果不重命名为新协议结果，不以仅重算 AUC 冒充重新运行。
