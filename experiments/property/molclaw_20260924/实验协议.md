# MolClaw 跨 benchmark 复现

源码：https://github.com/InternScience/MolClaw ，提交 180abb7679ffc5b1ca9974e7390e141d8098f642；归档 SHA256 4eff7ee885193eef4b89ac1ddac844cea0f2fa7fb8427b217f66a20719ede6af。

保留作者 Claude Code 运行时及完整分层技能库，使用 both（有技能）模式，不使用纯 LLM baseline 替代。作者运行入口通过 CLI 执行任务，并要求在 answer 标签中输出答案。百炼提供 OpenAI 兼容接口，因此使用仅监听服务器本机的 LiteLLM 代理转换协议，底层模型固定 deepseek-v4.1-flash。

SCP Hub 端点按官方源码使用 https://scp.intern-ai.org.cn/api/v1/mcp/2/DrugSDA-Tool 。密钥上传到 private/scp.env，权限 0600，不进入源码及结果。已验证初始化、81 个工具列表、乙醇 LogP/MR 的实际工具调用均成功。

使用此前相同的 ChatDrug 5600 条与 S²-mini MolOpt 1500 条输入及评价器。每题独立目录、独立 agent 会话，提供原任务指令，只接受一个最终 SMILES；无效或多分子最终提交均计失败。内部工具计算属于 agent 的工作流程，最终评价仅对最终提交调用一次，不对轨迹或候选集合取最佳。

作者提供了 max_iter=15 配置，但当前 run_claude.py 并未把它传给 Claude CLI，因此不能声称官方程序实际上限定 15 次。初始核验不私加候选数量、token 或检索相似度门槛，记录真实 turns、工具调用和 tokens；CLI 自身默认限制需与运行版本一起披露。不同 agent 不宣称等内部调用预算。

此为同任务、同评价的换后端复现，不是论文 Claude 后端成绩。先核验完整单题工具链，再覆盖任务设置做 pilot；模型和基础设施错误区分记录。MolLingo 的运行环境和进程不修改。

## 部署与核验记录

Claude Code 2.1.281、LiteLLM 1.102.0、MCP 1.30.0 安装在独立目录。LiteLLM 仅监听 127.0.0.1:18745，真实百炼 key 只在代理进程读取；agent 使用本机代理凭据和 SCP 环境变量。

初始调试单题 source_101_loose_000 跑通，唯一最终候选 O=C(NC[C@H]1C[C@@H](O)CO1)c1ccccc1N1CCCC1=O，有效且通过，运行时记录 27 turns。工具轨迹包含技能读取、SCP 性质计算、ADMET、mol2mol 生成、相似度、有效性和可视化。输入 token 79840、缓存读取 806784、输出 6735（CLI 返回口径，不转算费用）。

初始调试工作目录内曾有 case.json，轨迹显示 agent 读取了其中任务元数据，因此仅用于基础设施调试，不计入正式成绩。正式 pilot / full 已移除此暴露：case 元数据写到任务目录之外，agent 只接收原指令及单一最终答案格式要求。每题使用全新会话和配置目录，结果仅在 agent 结束后评分落盘。

长程会话 molclaw-experiment：先 runs/pilot（34 个设置），全部无运行错误后自动 runs/full（7100 条）。日志 experiment.log，退出状态 experiment.exit。此方法有多轮工具反馈，调用数及 token 与 MolLingo / ChatDrug / AgentDrug 不相同，不宣称等内部预算。
