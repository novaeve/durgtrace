# LIDDIA × SMDD Type4 单题验证协议

目前仅授权先看完整系统单题运行情况。迁移全部 340 题作为数据准备，不自动发起 340 题批量实验。

## 保留与适配

使用 LIDDIA 官方 Memory、决策提示模板、动作格式解析、历史组织和目标检查；使用官方 Pocket2Mol 权重与 GraphGA 交叉/变异/选择算法。聊天模型使用已获授权的 deepseek-v4.1-flash，temperature=1、seed=42、关闭 thinking，按此前 Type4 协议设置。该实验是 LIDDIA 的 SMDD 适配版，不是原论文数值复现。

公开输入从任务 input_files 白名单复制。首题固定 smdd_004_ABL1_1，不依据历史成功率选题。只把公开 description 与结构定位字段传给 agent；不把 witness、历史 solution、隐藏评测配置或评测结果反馈给 agent。复合物中的目标配体坐标定义 Pocket2Mol 的中心；去掉配体后使用真实蛋白原子，bbox 默认 23 Å。蛋白序列从公开复合物推导，不能直接把非白名单文件提供给 agent。

GENERATE 请求 100 个分子，Pocket2Mol 使用原配置 beam_size=300、max_steps=50，在 GPU 3 独立环境运行（PyTorch 2.7.1+cu128、PyG 2.5.3 和 pt27cu128 扩展，兼容 RTX 5090）。CPU 和 GPU 单样本 beam=1 只用于接口预检，不进入正式成绩。实际少于请求数或生成失败如实记录，不用其他生成器补齐。Pocket2Mol 官方旧格式权重以 weights_only=False 加载，仅限已审计官方 checkpoint。

GraphGA 原有 QED、SA 优化保留，原有 Vina 目标完全移除。用 Boltz-2 BindingAffinity 目标替代，并增加任务公开的 ADMET 优化目标。ADMET 改善量按公开目标阈值归一化后取 sigmoid；Boltz affinity_pred_value 越低越好，以 sigmoid(-value) 转成非负奖励。目标适配/奖励变换均属于明确的方法变更，不能解释为原论文原生实现。

LIDDIA 原先自动评估整批分子的 Vina 路径不使用。每批只自动计算 RDKit 本地指标；增加显式单分子 ADMET/BOLTZ 动作供 agent 选择。GraphGA 内部调用和显式调用共享同一个预测预算入口。CODE 保留生成 Python 函数筛选/组合分子的接口，但在无网络、无预测模型权重、无私有配置的隔离进程中执行。最终交单个 SMILES；不由隐藏评测选出最优分子。

## 预算与运行记录

每题 ADMET 最多 15 次、Boltz-2 最多 8 次；失败的实际调用也计数，不在后台免费重试。每次预测只允许一个分子。GraphGA 自身缓存可重用已经计算的同一目标值，但新的 backend 请求必计数。局部工具和原控制器只共用这一份预算记录。QED/SA 为本地描述符，无亲和力预测。

LLM 总调用最多 100 次（包含目标检查和 CODE 生成），累计 token 上限 10,000,000；单次未设人为输出上限，使用服务默认值并记录截断。达到总 token 上限后停止后续调用，因此最后一次请求可能跨过累计上限，与运行时停止策略一致。HTTP 重试由 SDK 处理，需注意 token 统计仅包含返回的响应。

首轮适配使用固定运行种子 42，每个生成/优化动作从固定种子的独立 RNG 顺序派生动作种子并记录，以保留重复生成可探索新候选的能力；不根据成败选择种子。接口预检使用动作种子 42，与正式实验分开。GraphGA 上层限制本地评分次数（QED 500、SA 300）； learned objective 在剩余共享预测额度内停止，可能在第一代即耗尽，不增加预算掩盖这种表现。

Vina 不注册、不调用、不作为备用；未测亲和力必须保持未知。SMDD 官方最终评测在提交后独立执行，评测自己的复测不反馈给 agent，不占 agent 的 15/8 探索预算。Boltz 使用原 Type4 的 10 diffusion/affinity samples、seed42、MSA server、potentials、max_parallel_samples=2。

基础设施诊断曾误用为 AgentD 安装的 Boltz 2.0.3，两个预检分别在并行数 2 和 1 时 OOM，均未进入 benchmark。随后核对旧 ChatDrug 使用的是全局 Boltz 2.2.1；建立 envs/boltz_smdd 虚拟环境，继承原运行时，并仅在虚拟环境覆盖 NumPy=1.26.4 和 RDKit=2024.9.6。前者解决 NumPy2.2.6 与 Numba0.61 不兼容，后者解决全局 RDKit 实际导入2022.09.5（安装元数据与导入版本不一致）无法读取分子缓存的问题。正式配置恢复并行数 2，使用 Boltz2.2.1、PyTorch2.13.0+cu130，不减少蛋白链或采样总数。环境版本仍需记录，不声称与旧机器结果逐位一致。
