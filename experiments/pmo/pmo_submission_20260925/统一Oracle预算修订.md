# 统一 oracle 提交预算（取代仅统计生成答案的口径）

用户进一步明确：答案提交就是提交给 oracle 查询。所有参考库评分、输入/候选反馈评分、初始模型答案及最终答案查询，都经过一个最多 1,000 次调用的入口。重复查询仍占次数，可缓存底层计算，但不退还逻辑查询预算。无效输入只要提交至该入口也占次数。模型输出尚未送入 oracle 时不自动当作已查询。

先前 runs/chatdrug 与 runs/agentdrug 把内部参考查询排除在答案预算之外，已暂停，不能作为本协议成绩。新任务写入 runs_oracle_1k，旧结果不覆盖、不事后伪装为新运行。

同一口径的 AUC 由全部 oracle 提交轨迹构建，包含参考分子；规范化去重保留首次查询序号，不压缩重复位置。已评分的最终答案仅作展示不会人为再发一次查询；原算法实际发起的重复评分请求仍计次。自然结束与用满预算分别标识。

原生结构的后果：AgentDrug 在模型编辑前为原固定参考库计算目标性质。在本配置下，初始模型答案占 1 次，接下来的 999 次参考查询即用完预算，剩余库未评分，模型编辑阶段不启动。不裁剪参考库、不免费预评分、不暗加预算来改变这个结果。该结果测试的是此原生流程在当前 oracle 预算下的可执行性；不等于编辑模型生成能力得分。

ChatDrug 保留原相似检索顺序及反馈轮数；其实际调用的参考评分同样计入。两组共用对照组首个模型答案作为用户授权的起点，无额外公共搜索或历史。DeepSeek 对照组原来每次输出对应一次 oracle 提交，已有计数符合这条规则，保持运行。

MT-Mol 的源码按外层迭代记录答案，这是源码事实；本次“所有内部 oracle 查询也统一收费”是用户明确指定的评价协议，不声称 MT-Mol 原实现已经对所有内部调用作同样计费。

已执行验证：4 项预算/反馈/断点测试通过；QED 实际试跑通过。ChatDrug 自然结束时 3 次查询（初始答案、起点反馈、候选反馈各 1）；AgentDrug 恰好 1,000 次（初始答案 1、参考库 999），新增编辑模型调用 0。随后已开始两组各 23 目标运行。tmux pmo-oracle-1k-editors，日志 oracle_editors.log；旧 pmo-model-init-editors 仍暂停，不能恢复为当前实验。
